# PDF 排版优化实施结果

日期：2026-09-06。生产模板版本：`glyphweave-pdf-2`。本次在既有宋体正文、黑体标题、A4 版心、13.5pt 标题与编号、列表缩进、代码行号和克制配色上实施局部优化。依据及其适用边界见 [v2 方案](TYPOGRAPHY-SPEC.md)，历史对照见 [首轮检查](README.md)。具体参数是项目设计选择，不是标准规定的唯一数值。

## 已实施的排版规则

| 部分 | 最终行为 | 原因与验证 |
| --- | --- | --- |
| 正文 | 默认 10.5pt、400 字重、基础 tracking 为 0；普通行基线间距 16.8pt | 按当前字体的自然行框测量 leading，10.5pt 与 11pt 两档真实编译均达到 1.6 倍；高公式仍可撑高行框 |
| 中英文 | 中文宋体与 Libertinus Serif 拉丁分工；`covers: "latin-in-cjk"` 保留中文标点字形 | 移除全局 ASCII 盒子；原生中西文边界间距和英文断词恢复，手工空格不叠加额外边界间距 |
| 强调 | 中文强调用加粗正体；英文强调保留真实斜体 | 本机和 Noto 样张均检查；PDF 实际嵌入 Libertinus Serif Italic |
| 数学 | 独立 New Computer Modern Math；移除全局/行内盒子基线干预 | 测试公式宽度与同字号原生 Typst 对照相同，数学变量恢复原生字形 |
| 标题 | 维持 13.5pt；editorial 字重 600、portable 字重 700；各级标题统一上方 18pt、下方 12pt | 匹配默认苹方与 Noto 字重，保留已有标题编号和紧凑风格 |
| 代码 | 代码块 8.5pt、普通行距目标 1.45 倍，行号 7.5pt；行内代码 0.88em | 原生行内断行替换不可拆盒子；提取 PDF 后路径完整，无人为插入软连字符 |
| 表格 | 正文 9pt、目标行距 1.5 倍；figure 内表格可跨页 | 80 行表格全部保留，跨页重复原生 table.header |
| 图注 / 脚注 | 8.5pt，目标行距 1.5 倍 | 最终逐页检查无重叠和裁切 |
| 参考文献 | 9pt，目标行距 1.5 倍 | 正文放大后曾单独溢出第 3 页；独立字号处理后首轮为 2 页；本次增加标题/公式留白后最终为 3 页 |

行距校准使用固定样串 `中文Agpq` 的一行与零 leading 双行高度差，求出自然基线间距，再补足目标。它不是强制行网格，复杂公式、其他脚本或用户自定义样式可改变个别行高。不再使用全局 0.04em baseline 修正；这次两套字体组合的视觉检查没有发现需要重新加入此补偿的证据。

## 配置与构建

`typst.pdf.template` 新增 `profile`、`fontSize`、`latinFonts`、`headingFonts`，原有正文/代码字体覆盖继续有效。省略字段按 profile 补全；`latinFonts: []` 可使用中文正文栈的拉丁字形。其他字体栈要求非空，避免意外依赖不明确的空栈回退。

- `editorial`：Songti SC 优先、Noto Serif CJK SC 后备；标题 PingFang SC 优先；代码 Menlo 优先。
- `portable`：Noto Serif CJK SC、Noto Sans CJK SC、DejaVu Sans Mono。Pages 示例使用此配置。
- 丢失字体家族以去重后的 `typst-font-missing` 写入 manifest。portable 将编译中出现的 unknown font family 视为失败，最终由 `pdf.failure` 决定整站失败或跳过 PDF。这也会覆盖源文档另行指定的缺失字体。
- 两种配置均不自动下载字体或固定版本；低层编译 API 不传配置也会正确使用完整默认值。
- 模板版本升级，沿用既有模板/字体指纹与缓存失效机制。

## 验证结果

本机 macOS、Typst 0.15.0、Poppler。全部命令成功完成：

```sh
pnpm check
pnpm build:demo
node scripts/verify-integration.mjs
TYPST_FONT_PATHS=/path/to/pinned-noto-fonts node scripts/verify-pdf-typography.mjs
pnpm test:package
```

- 72 项单测，13 个文件；Lint、TypeScript、Astro 检查通过，Astro 无错误、警告或提示。
- 原有真实 Typst HTML/PDF、包含/宏/引用、增量失效及输出字节一致性集成检查通过。
- 新增真实 PDF 集成覆盖中西文边界间距、数学对照、英文断词、两档字号行距、路径提取、80 行跨页表格与重复表头、实际字体、无参编译和 portable 缺失字体失败。
- 独立打包安装 smoke 通过，确认新增 schema 与编译器依赖可在发布包中使用。
- 真实站点生成的最终文章逐页栅格检查 3 页；Noto 对照同样检查全部 3 页。正文、图注、脚注、表格、公式及参考文献均未观察到重叠或越界。没有通过缩小正文来维持页数。

最终站点样张保存在 `output/pdf/typography-optimized.pdf`，为构建产物的副本。Noto 实验文件版本、来源路径和 SHA-256 保存在 [font-provenance.json](font-provenance.json)，字体二进制不放入仓库。历史 A/B/C 脚本现读取冻结的 [baseline.typ](baseline.typ)，不会把优化后的模板误当作旧基线。

## 验证边界

Noto 配置是在本机加载固定字体文件验证的，尚未实际执行 Linux CI；新增测试已接入现有 Linux 集成工作流。没有宣称跨系统逐字节排版相同，也没有进行出版标准符合性认证、全部标点禁则覆盖或所有用户文档的穷尽检查。当前默认字体可用性、真实字重和字形范围仍受安装环境影响；editorial 中缺失但未被采用的后备字体警告并不等同于实际缺字。

## 标题与大型公式间距修正（用户复核后）

上一轮“无重叠或裁切”的检查不足以判断间距是否舒适。用户指出标题下方与大型公式之间偏挤，本轮以实际块高度和 PDF 文本框坐标重新验证，修复如下。

- 原标题规则对浅层使用 `below: 8pt`、深层使用 `6pt`。相同字体探针的可提取文字框间距分别约 4.02pt 和 2.02pt，确实偏小且不统一。所有层级现使用 `above: 18pt, below: 12pt`；原生 sticky 保留。相同探针的文字框间距统一为约 8.02pt。字体框与可见笔画边缘并非同一概念，不把文字框度量冒充精确视觉墨迹距离。
- 原独立公式块间距为 `0.45em`，默认字号下仅 4.725pt，连续积分、分式、矩阵与分段函数显得挤。移除额外的 block/align 包装，在原生 equation 上设置上下各 `1em`。相邻块按 Typst 间距合并规则形成 10.5pt 的单个间距，不是相加成 21pt。
- 多行对齐公式原来继承中文正文的校准 leading。现独立设为 `0.5em`；在默认字号下双行普通等式测得行间净增量为 5.25pt，复杂行仍按实际公式高度排布。保留原生居中、编号与公式不跨页行为。

采用 [Typst 官方 block 文档](https://typst.app/docs/reference/layout/block/) 所示的 show-set 控制数学块间距，并保留 [heading 文档](https://typst.app/docs/reference/model/heading/) 要求的块级标题与 sticky 行为。12pt、1em、0.5em 是本项目经样张检查采用的参数。

真实渲染回归新增四级标题与正文的间距、连续大型公式间距及多行公式内部间距，均在 10.5pt / 11pt 和 editorial / portable 两组字体下通过。完整 `pnpm check`（72 项单测）与原有集成检查再次通过。最终文章自然增加到 3 页；图片与完整公式的不可拆分布局会在页末保留空白，未通过压缩已修复的间距强行维持两页。

## 代码块视觉修正（用户复核后）

原代码块使用 `#f7f7f4` 全宽底色与左侧 `0.6pt` 竖线，与正文和公式的开放版式相比，形成较突出的独立面板。本轮移除代码底色和边框，同时删除不再使用的 `soft` 色值。

代码区域通过原有等宽字体、灰色行号和留白建立边界：8.5pt 字号、1.45 倍普通行距、7.5pt 行号、横向 9pt / 纵向 6pt 内缩及上下 1.1em 间距均保留，原生语法高亮与跨页能力保留。本次只改变绘制装饰，没有缩放代码或改动行号结构。

重新执行真实站点构建并检查最终全部 3 页：代码融入白色页面，行号及代码仍清晰可辨，分页未变。真实 PDF 排版集成检查通过。此次没有为纯装饰常量新增字符串断言；此前的整体测试结果属于对应实施阶段。

### 代码水平位置微调

随后按用户反馈将横向内缩从 9pt 减至 0pt，行号与代码的列间距从 0.75em 增至 1em（8.5pt）。行号左移 9pt，代码起始位置净左移约 6.875pt；行号列宽、纵向留白、字号和行距保持原值。重新构建并逐页检查最终 PDF，仍为 3 页。
