# PDF 排版规范与参数方案 v2

> 后续实施已完成：见 [实施结果与验证](IMPLEMENTATION.md)。本文保留实施前的研究状态与实验数据，生产配置以实施报告和使用文档为准。

日期：2026-09-06。用途：完善 Glyphweave 简体中文技术长文的 PDF 优化计划。授权范围为研究、测量和方案，不修改生产模板。本文件接续 [首轮检查](README.md)，具体取值均为待视觉验证的设计候选，除非明确标注为已测量。

## 1. 依据与适用边界

| 来源 | 本轮核对内容 | 如何使用 |
| --- | --- | --- |
| [CY/T 154—2017《中文出版物夹用英文的编辑规范》](https://www.nppa.gov.cn/xxgk/fdzdgknr/hybz/202210/t20221004_445147.html) | 官方登记为现行；已读官方 PDF 第 8–12 章 | 混排字体搭配、字号协调、英文空格/断词、斜体及数字的直接行业参考 |
| [GB/T 15834—2011《标点符号用法》](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=22EA6D162E4110E752259661E1A0D0A8&refer=outter) | 官方登记为现行；本轮教育部全文链接读取失败 | 纳入标点校验依据，但不把未核对条文作为已完成验收的证据 |
| [W3C《中文排版需求》2026-09-01 版](https://www.w3.org/TR/2026/DNOTE-clreq-20260901/) | §6.1、6.3、7.1 的混排、禁则和行距说明 | 作为排版实践资料；其状态是 Group Note Draft，不是 W3C Recommendation，也不是强制标准 |
| [Typst text](https://typst.app/docs/reference/text/text/) 与 [par](https://typst.app/docs/reference/model/par/) | 字体匹配、字符/词间距、基线、leading 与两端对齐限制 | 工程语义；本地 0.15.0 的行为用独立探针验证，不仅依赖可更新的网页 |
| [WCAG 1.4.12 解释](https://www.w3.org/WAI/WCAG21/Understanding/text-spacing) | 指标约束用户覆盖样式后的适应能力，并不要求作者默认采用全部数值 | 不把 0.12em 字距、2em 段距机械搬进固定版式 PDF |

行业规范概括：宋体类中文通常配衬线英文，黑体类中文配无衬线英文；中英字号需协调。中英文边界是否留空由字体和视觉效果决定，但体例应一致，英文与中文标点之间不另加空格；英文断词按英文规则；英文书刊名使用斜体。以上来自 [CY/T 154—2017 第 8–12 章](https://www.nppa.gov.cn/xxgk/fdzdgknr/hybz/202210/P020221004608768453140.pdf)，并不意味着某个具体字体或 10.5pt 是唯一选择。

CLREQ 草案把普通横排中西文边界的基础间距讨论在不超过 1/4em 的范围内，另有两端对齐时的调整规则；其常见字框间行距为字号的 50%–100%，须结合行长。把它转译为 Glyphweave 的具体参数属于下面的项目设计，不是照抄标准数值。

**目标**：长时间阅读时，中文字形清晰，英文不突兀，语义强调可辨，段落灰度稳定，数学和代码保持正确。暂不追求公文版式、古籍竖排或某家期刊模板；也不宣称完成了标准符合性认证。

## 2. 字体与字重：从名称列表改为有职责的字体组合

### 2.1 候选组合

| 候选 | 中文正文 / 英文正文 | 标题 | 代码 / 数学 | 取舍 |
| --- | --- | --- | --- | --- |
| F0 历史基线 | Songti SC 及其内置拉丁字形 | PingFang SC | Menlo / New Computer Modern Math | 保留熟悉外观，英文斜体支持不足 |
| F1 本机协调候选 | Songti SC / Libertinus Serif | PingFang SC，先使用其自带拉丁字形 | Menlo / 同上 | 首选做本机样张；英文正常体、粗体、斜体齐备，但字面比例须复核 |
| F2 可复现候选 | Noto Serif CJK SC / Libertinus Serif | Noto Sans CJK SC，先使用其自带拉丁字形 | DejaVu Sans Mono / 同上 | 首选做跨平台对照；本轮未安装 Noto CJK，尚无优于 F1 的视觉证据 |

F1/F2 是工程候选，并非标准指定搭配。Noto 的发行入口为 [官方仓库](https://github.com/notofonts/noto-cjk)；进入实验时固定具体 SC 文件、版本和 SHA-256，不能只写“安装最新版”。本机系统字体不复制进发行包。MiSans 仍不恢复为默认。

**字体选择顺序**：先定中文字体，再匹配英文的小写字面、粗细和基线；最后才做英文相对字号微调。第一轮英文缩放 1.00，必要时仅试 0.98 / 1.02，整篇按角色一致。保留 kerning、标准连字；代码维持等宽与原始字符，不给数学变量套正文正则。

实施时定义 `bodyCjk`、`bodyLatin`、`heading`、`mono`、`math` 五个角色。拉丁字形覆盖应通过字体描述符/脚本范围控制；不能简单把拉丁字体置顶就假定中文引号、破折号和省略号一定取自中文字体。先核对 0.15.0 的覆盖能力，再检查实际字形来源。

### 2.2 已核对的本机字重

证据：[font-variants.txt](font-variants.txt)，来自 `typst fonts --variants`，已去掉本机路径。

| 字体 | 实际可用样式 | 对计划的影响 |
| --- | --- | --- |
| Songti SC | 正体 300 / 400 / 700 / 900；无斜体 | 正文用 400，强强调用真实 700；不设计虚构的 450、500 或 600 中间档 |
| STSong | 仅正体 300 | 不把它当作与 Songti SC Regular 完全等价的降级字体 |
| PingFang SC | 正体 100 / 200 / 300 / 400 / 500 / 600 | 标题 600，较弱层级可试 500；避免请求不存在的 700 来制造层级 |
| Libertinus Serif | 正体与斜体均有 400 / 600 / 700 | 可承接英文正文与英文书刊名的真实斜体 |
| Menlo / DejaVu Sans Mono | 正体与斜体均有 400 / 700 | 代码正文 400，语法突出允许 700 |

项目规则：不得通过描边、压缩字宽或假倾斜来弥补缺失样式。中文 `emph` 的语义仍保留，呈现先比较“保持正体并使用适度字重差异”；楷体或着重号仅作为独立候选，不在全篇悄悄替换。英文 `emph` 使用真实 italic，数学继续使用数学字体。英文书刊名、普通强调和变量不是同一类样式规则。

字体不足时给出可定位诊断，发布用 profile 检查实际匹配结果；不允许一个字符静默降级到黑体、下一个又回宋体而无人知晓。F0 可保留为兼容 profile，新的固定 profile 则要求所需字体完整。

| 角色 | 当前 | v2 首选候选 | 规则 |

## 4. 字间距：分别控制四件事

| 对象 | 推荐基线 | 微调与验收 |
| --- | --- | --- |
| 汉字之间 | `tracking: 0pt` | 不全局疏排；0 / +0.005em / +0.01em 只在字号和字体确定后试验 |
| 英文单词内部 | 自然字距、kerning 开启 | 不为让英文“占格”任意拉宽；标题也先保持 0 tracking |
| 英文单词之间 | `text.spacing: 100%` | 两端对齐沿用现有 85%–120% 为初始偏好，记录实际异常空白 |
| 中西文边界 | `cjk-latin-spacing: auto` | 原生普通诊断串约 0.25em/边界；不是正文每个字符都加 0.25em |

0.125 / 0.20 / 0.25em 可作为后续中西文边界的实验档位，**但当前 `cjk-latin-spacing` 只接受 auto/none**，不能写成 `cjk-latin-spacing: 0.2em`。第一阶段选 auto；只有它无法满足样张要求时，再评估保留文本语义的专用边界处理，禁止回到逐词 box。

修订首轮结论的解释边界：59.32pt 对 64.32pt 证明了盒子让 Typst 原生自动边界间距失效；它不证明所有中文文稿“无间距就违反标准”。本项目选择自动间距是为了混排一致性。

两端对齐的初始 tracking 调整仍维持 `[-0.01em, +0.01em]`，不要把它与固定 `text.tracking` 混淆。Typst 文档明确指出空格在无其他可行断行方式时仍可突破 max，因此 120% 不是硬保证。项目验收要检查渲染结果，不能仅断言配置值。此语义见 [par 的 justification-limits](https://typst.app/docs/reference/model/par/#parameters-justification-limits)。

对中文标点不统一加空格；使用大陆简体字形与禁则。两字符中文省略号、破折号的整体性，中文引号方向及行首行尾位置，分别做用例。先验证原生断行，再考虑局部补偿；不全局打开 `palt` / `halt` 或靠负 tracking 压缩所有标点。源文字符纠错应可见，排版模板不改写代码、URL、数字或引用原文。

## 5. 行间距与段间距：以实际行高为验收对象

### 5.1 新测量改变了上一轮的调参方向

Typst 的 leading 是行框边缘之间的空白；行框由字体及 text edges 决定。对同样内容重复三行，用 `(三行高度 - 单行高度) / 2` 测普通文本的行高。探针没有生产 show 规则，也没有复杂行内公式，不能直接替代最终 PDF 检查。

45 个测量见 [line-metrics.json](line-metrics.json)，源码 [line-metrics.typ](line-metrics.typ)。Typst 0.15.0、本机 10.5pt 样例：

| 字体 | leading | 实测行高 | 行高 / 字号 |
| --- | ---: | ---: | ---: |
| Songti SC | 0.72em | 14.8575pt | 1.415 |
| Songti SC | 0.80em | 15.6975pt | 1.495 |
| Songti SC | 0.905em | 16.8000pt | 1.600 |
| Songti SC | 0.955em | 17.3250pt | 1.650 |
| PingFang SC | 0.80em | 17.4300pt | 1.660 |
| Libertinus Serif + Songti SC | 0.80em | 15.6975pt | 1.495 |

所以，不再优先尝试把宋体 leading 从 0.8 降到 0.72；它在该样例中会让行高进一步变紧。也不能把所有字体设为同一个 leading 就称作行高统一。

### 5.2 项目目标与推导

普通正文初选 **实际行高 1.60–1.70 倍字号**，对照档位为 1.50 / 1.60 / 1.65 / 1.70。这是针对当前细宋体、技术内容与 A4 阅读的设计假设，不是普适最佳值。10.5pt 对应 16.8–17.85pt。

固定字体和字框时，设字号为 S、leading 为 L、有效行框高度为 E，普通重复行满足 `P = E + L`。由 Songti 样例可得 E/S = 1.495 - 0.8 = 0.695；故目标 P/S = 1.60 时，L/S = 0.905。该值已经用探针复验。换字体、混入高公式或调整基线后必须重测，不能永久硬编码为所有字体的规则。

第一种实现是按 profile 校准 leading，保留自然字体边缘；备选才是统一 text edges。不要直接把中文行框强制设死来压住公式高度，避免上标或重音碰撞。

段落以 **首行缩进 2em + 小幅额外段落间隔** 为主。建议普通相邻段落的基线跨距约 `P + 0.15S`，相应 `par.spacing = leading + 0.15em`，不是在 P 之外再加一整行。当前 leading 0.8em / spacing 1em 的差额本来只有 0.2em，不应误判为“多了一整行”。

代码块、表格、图注分别校准：普通代码行高初选 1.40–1.50 倍代码字号，表格/图注 1.45–1.60 倍其字号。中文注释、嵌套列表、脚注和公式采用独立压力样例。复杂公式允许必要撑高或改为块级；优先保证无重叠，再追求节奏一致。

## 6. 版心与块级节奏

先保持现有 A4 与 459.21pt 版心；正文改为 10.5pt 后约容纳 43.73 个全角字。若仍感觉扫视距离偏长，再试 **42em = 441pt ≈ 155.58mm**，与当前约 162mm 对照。42 字是项目设计候选，不借用网页无障碍条款宣称为 PDF 标准。

标题仍保留统一 13.5pt。留白候选以“章前大于章后”为原则：二级标题上 16pt / 下 8pt，三级上 12pt / 下 6pt，与现有上下相等的 1.05em 对照。这一步最后再做，防止字体变化导致的分页与块间留白变化混在一起。

列表继续保留原缩进与标记，先测 tight/loose 及嵌套的实际间距；不要以 `list.spacing: 0.95em` 推断每个列表项固定相隔 0.95em。图与图注保持成组，长表则必须验证可分页。页末标题尽量至少带两行正文，孤立一行作为项目检查项；不为满足整页栅格造成大块空白。

## 7. 实施与验证矩阵

| 阶段 | 固定项 | 变量 | 决策门槛 |
| --- | --- | --- | --- |
| M0 机制修复 | 当前字体、字号、页面 | box → text baseline / 原生对照 | 首轮混排、数学、断词缺陷不复现 |
| M1 字体字重 | 10pt、相同测得行高、页面 | F0 / F1 / F2 | 字体实际匹配、真实粗斜体、中文标点字形均正确；不能靠不同密度获胜 |
| M2 字号行高 | 胜出的字体 | 10 / 10.5 / 11pt，先固定行高比再分档 | 100% 与适页检查；长段找行、细字清晰度和翻页负担综合判断 |
| M3 间距与结构 | 字体、字号、行高 | 微 tracking、段距、标题留白、42em 版心 | 中西间距一致，无白缝、禁则错误、孤行或内容裁切 |
| M4 跨平台回归 | 选定 profile 与固定字体文件 | macOS / Linux，同一 Typst | 字体与文本完整，普通行高在预定容差内，PDF 提取顺序正确 |

每个阶段先用诊断集调参，再用未参与选择的真实长文作保留验证集。每轮保留失败样张与影响记录，不把更少页数当唯一优势。人工比较隐藏候选名称、使用相同缩放和屏幕条件；没有用户阅读实验时，只称视觉复核，不报告“阅读速度提升 X%”。

项目硬性门槛：无缺字、无意外字体降级、无文字重叠/裁切、关键禁则用例通过、代码/链接复制内容不变、英文斜体与数学语义正确。普通三行探针的目标行高允许 ±0.2pt 校准误差；此容差为工程取值，不适用于含复杂公式的行。

工程落点沿用首轮计划：schema、types、core、compiler、prelude 同步。面向用户优先暴露 `profile` 与字号；内部维护字体角色、实际字重、测得行高和各块 tokens，避免几十个不受约束的旋钮。字体清单记录文件哈希、选中 face 与缺失行为；复用已有编译器/字体缓存指纹。视觉回归用固定版本字体分别建立基准，保留现有发布字体检查。

## 8. 推荐进入下一轮的具体样张

首选 **F1 + 正文 10.5pt/400 + 实际行高 1.60 倍 + 中文自然字距 + 原生中西间距**。标题维持 13.5pt/600，代码块 8.5pt，图注与脚注 8.5pt。它代表一个可验证的起点；F2 使用相同目标行高做跨平台对照。

一个完整例子：`中文API中文，见 Learning Theory。` 中，中文与逗号由中文字体承担，API 与英文书刊名由英文角色承担；仅书刊名使用真实 italic；API 两侧由引擎处理边界间距，逗号前不再人为加空格。10.5pt 普通文本目标行高 16.8pt；长英文在允许的语言段内按规则断词；代码和数学走各自角色。最终确认的是可见字形、实际距离及文本完整性，而不仅是配置文件写了哪些数值。

本轮新增证据为官方来源核对、本机字体 inventory 和 45 组行高测量。没有生成 v2 整页视觉样张，没有证明 F1/F2 或 10.5pt 胜过所有方案，生产模板保持不变。

复现行高度量：

```sh
typst query docs/reports/pdf-typography-2026-09-06/line-metrics.typ metadata --field value
typst fonts --variants
```

Typst 0.15.0 会提示 query 已弃用，但仍可运行。保存的 JSON 中 `leading_em` 使用数值，避免长度的 `repr` 四舍五入使 0.905 被误记为 0.91。
